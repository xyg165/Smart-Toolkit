# filekit · 文件整理工具箱

> 一个脚本，三件事：**规范文件名**、**读内容归类**、**一键回滚**。
> 单文件，无框架，复制走就能用。

## 功能一览

| 功能 | 说明 | 可用模式 | 需要依赖 |
|---|---|---|---|
| **文件名清理** | 去空格、非法字符、括号，去"最终版/副本/final"等废话词 | 全部 | 否 |
| **类型前缀** | 按扩展名自动加 `IMG`/`DOC`/`XLS`/`PPT`/`PDF`/`AUD`/`VID`/`ZIP` | 全部 | 否 |
| **内容归类** | 读文档正文，判断属于 38 类中的哪一类 | classify / auto | **是** |
| **图片 OCR** | 对图片做中文 OCR，再判断类别（发票、合同扫描件）| classify / auto | **是（系统级）** |
| **时间戳入名** | 文件名末尾加 `YYMMDDHHMM`（精确到分钟）| 全部 | 否 |
| **版本号保留** | 原文件名里的 `v1`/`v2` 原样保留 | 全部 | 否 |
| **数字补零** | `头像1` → `头像01`（排序正确）| 全部 | 否 |
| **三级防冲突** | 时间戳 → 序号 → 疑似同名报告 | 全部 | 否 |
| **疑似同名报告** | 发现同一文档多份时，列清单由你决定 | 全部 | 否 |
| **预览模式** | 默认不改任何文件，只看会改成什么 | 全部 | 否 |
| **日志留痕** | 每次执行写 JSON 日志（谁改成了什么）| 全部 | 否 |
| **一键回滚** | 按日志逆序还原到改动前 | rollback | 否 |
| **智能模式** | 能读到内容就归类，读不到就只按文件名 | auto | 视情况 |

> ✅ **零依赖**：`rename` 模式与全部安全功能，只用 Python 标准库
> ⚠️ **需要依赖**：只有 `classify` / `auto` 的内容识别部分需要（见下方安装）

---

## 三种模式怎么选

| 场景 | 用哪个模式 |
|---|---|
| 文件名本来就有信息（`采购合同 v1.docx`）| `rename` |
| 文件名没信息（`文档1.docx`、`未命名.docx`）| `classify` |
| 一堆文件混着，有的有名有的没名 | **`auto`** |

```bash
python filekit.py rename    --dir ./素材            # 只按文件名
python filekit.py classify  --dir ./文档            # 读内容归类
python filekit.py auto      --dir ./混合文件夹       # 智能判断
python filekit.py rollback  ./_filekit_log_xxx.json  # 回滚
python filekit.py doctor                              # 检查环境依赖
```

## 快速开始

```bash
# ① 先预览（什么都不改）
python filekit.py auto --dir "./我的文件夹" --verbose

# ② 确认没问题，执行
python filekit.py auto --dir "./我的文件夹" --apply

# ③ 反悔了
python filekit.py rollback "./我的文件夹/_filekit_log_20261007_160841.json"
```

## 命名规范

```
[类型]_[分类]_[清理后原名]_[版本]_[YYMMDDHHMM].[后缀]
  ↓      ↓         ↓          ↓         ↓
 DOC    合同    采购合同       v1    2609151030
```

### 举例

| 原文件名 | 修改时间 | 结果 |
|---|---|---|
| `文档1.docx` | 2026-09-15 10:30 | `DOC_合同_文档1_2609151030.docx` |
| `工作簿1.xlsx` | 2026-09-15 10:30 | `XLS_报价单_工作簿1_2609151030.xlsx` |
| `方案 final 版.docx` | 2026-10-07 09:15 | `DOC_方案_方案_2610070915.docx` |
| `头像1.png` | 2026-10-07 09:15 | `IMG_头像01_2610070915.png` |
| `扫描件001.png` | 2026-10-07 11:20 | `IMG_发票_扫描件001_2610071120.png` |
| `随便写写.docx` | 2026-10-07 11:20 | `DOC_未分类_随便写写_2610071120.docx` |

### 时间戳读法

```
2609151030 = 26年 09月 15日 10:30
2610070915 = 26年 10月 07日 09:15
```

取值来源：**文件修改时间** —— 所以同一文档的不同版本，时间戳天然不同。

## 安装依赖（只有 classify / auto 需要）

```bash
# Python 库
pip install python-docx openpyxl python-pptx pypdf

# PDF 文本提取 + 图片 OCR
apt install poppler-utils tesseract-ocr tesseract-ocr-chi-sim    # Debian/Ubuntu
dnf install poppler-utils tesseract tesseract-langpack-chi_sim   # RHEL/CentOS
```

> 缺哪个格式的依赖，只有那个格式会读不到内容（标为「未分类」），不影响其它格式。
> `rename` 模式完全不需要这些。

### 环境自检（下载后先跑这个）

```bash
python filekit.py doctor
```

**依赖齐全时**：
```
✅ 环境检查：内容识别所需依赖齐全
```

**缺依赖时**（会告诉你缺什么、怎么装）：
```
⚠️  环境检查：以下依赖缺失 —— 对应格式将标为「未分类」（其它功能不受影响）
   · tesseract 中文语言包 chi_sim
       装法：apt install tesseract-ocr-chi-sim  /  dnf install tesseract-langpack-chi_sim
   提示：只做重命名不读内容的话，可以忽略以上缺失（用 rename 模式）
```

> ⚠️ **图片 OCR 依赖 tesseract + 中文语言包**，这是**系统级依赖**，pip 装不上。
> 缺了不会崩溃 —— 对应文件会标「未分类」；`rename` 模式完全不受影响。
>
> **如果你只需要重命名**（不需要读内容判断类别），那就**什么都不用装**。

## 内置分类（38 类）

| 大类 | 分类 |
|---|---|
| **商务经营**（9）| 合同 · 保密协议 · 报价单 · 招投标 · 采购订单 · 发票 · 付款凭证 · 客户资料 · 销售合同 |
| **项目产品**（7）| 需求文档 · 方案 · 项目计划 · 测试报告 · 验收文档 · 项目周报 · 产品文档 |
| **技术研发**（6）| 技术文档 · 设计文档 · 说明书 · 图纸 · 知识产权 · 技术标准 |
| **行政人事**（7）| 规章制度 · 通知公告 · 会议纪要 · 简历 · 人事档案 · 培训材料 · 工作总结 |
| **财务**（3）| 财务报表 · 预算 · 报销单 |
| **内容运营**（3）| 内容脚本 · 运营数据 · 素材清单 |
| **法律与其他**（3）| 法律文书 · 资质证书 · 分析报告 |

**判定算法**：强特征词（3 分）+ 一般词（1 分）加权打分，总分 ≥ 4 且明显领先才定类，否则标「未分类」（不硬猜）。

## 参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--dir PATH` | 目标文件夹 | 必填 |
| `--apply` | 真正执行（不加则只预览） | 关闭 |
| `--sep CHAR` | 分隔符 | `_` |

| `--pad` | 末尾数字补零 | 关闭 |
| `--verbose` | 显示分类候选及得分（排查识别不准）| 关闭 |

## 三级防冲突

| 层级 | 场景 | 处理 |
|---|---|---|
| **1** | 不同时间保存的版本 | 时间戳区分（`_2610070915` vs `_2610071045`）|
| **2** | 同一分钟内的同名文件 | 加序号（`_2610071005` vs `_2610071005_02`）|
| **3** | 疑似同一文档多份 | **主动列清单报告** |

```
⚠️  发现 1 组疑似同名文档（可能是同一文档的多个版本）：
  · DOC_方案  →  4 份
        DOC_方案_2610070915.docx
        DOC_方案_2610070945.docx
        DOC_方案_2610071005.docx
        DOC_方案_2610071005_02.docx
  → 时间戳已把版本区分开；如需精简，请确认后手动删除过期版本
```

**它从不删文件** —— 只报告，删不删你决定。

## 安全设计

| 机制 | 说明 |
|---|---|
| **默认预览** | 不加 `--apply`，一个文件都不动 |
| **日志留痕** | 每次执行写 `_filekit_log_YYYYmmdd_HHMMSS.json` |
| **一键回滚** | `rollback <日志>` 按日志逆序还原 |
| **不覆盖** | 重名自动加 `_02 _03` |
| **不改内容** | 只动文件名，不碰文件内容 |

## 扩展分类

打开 `filekit.py`，在 `CATEGORIES` 里加一段：

```python
"无人船项目": {
    "strong": ["无人船", "船体", "推进器", "自主航行", "遥控"],
    "weak": ["水域", "船载", "航行", "水面"],
},
```

**要点**：`strong` 放该类独有的词（高辨识度），`weak` 放通用词。这样加多少类都不会互相干扰。

## FAQ

**Q：会改坏我的文件吗？**
A：不会。只改文件名；默认预览；有日志；可回滚；从不删除、不覆盖。

**Q：识别错了怎么办？**
A：用 `--verbose` 看候选得分，然后把这类关键词改准（加独有的强特征词）再跑。

**Q：为什么标「未分类」？**
A：内容特征不足（比如随手写的便签）。这是**有意设计**——宁可标未分类，也不要猜错。

**Q：处理 1000 个文件要多久？**
A：纯文本/Word 很快（几十秒）；带 OCR 的图片每张 1-3 秒。

**Q：会递归子文件夹吗？**
A：目前只处理指定目录的第一层。

## 工作原理

```
扫描目录
   ↓
[rename]  跳过内容读取
[classify/auto]  按扩展名提取正文（最多 12000 字）
   ↓
[classify/auto]  38 类加权打分 → 定类 / 未分类
   ↓
清理文件名（去空格/非法字符/废话词）
   ↓
拼装：类型前缀 + 分类 + 原名 + 补零 + 时间戳
   ↓
冲突处理（序号）+ 疑似同名检测
   ↓
预览  →  --apply  →  执行 + 写日志
```
