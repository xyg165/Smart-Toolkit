# classify_kit · 文档内容自动归类工具

> 不看文件名，**读文档内容**判断它是合同、发票还是方案 —— 然后把归类写进文件名。

## 为什么需要它

整理旧文件时，最常见的场景是：

```
文档1.docx           ← 这是啥？
新建文档.docx         ← 这是啥？
工作簿1.xlsx          ← 这是啥？
未命名.docx
演示文稿1.pptx
扫描件001.png        ← 发票扫描件？
```

**文件名没信息，但内容里有。** `文档1.docx` 打开一看是采购合同，`工作簿1.xlsx` 里是报价单。

`classify_kit` 做的就是：**打开每个文件读一遍，判断它是什么，然后写进文件名**。

```
文档1.docx    →  DOC_合同_文档1_2610070915.docx
工作簿1.xlsx  →  XLS_报价单_工作簿1_2610070915.xlsx
扫描件001.png →  IMG_发票_扫描件001_2610070915.png
```

---

## 特性

- ✅ **38 个内置分类** —— 覆盖商务/项目/技术/行政/财务/内容/法律七大领域
- ✅ **读内容判断** —— PDF / Word / Excel / PPT / 文本 / **图片 OCR**
- ✅ **加权打分** —— 强特征词（3 分）+ 一般词（1 分），判不准就标「未分类」（不硬猜）
- ✅ **时间戳入名** —— `YYMMDDHHMM`（精确到分钟）
- ✅ **三级防冲突** —— 时间戳 → 序号 → 疑似同名报告
- ✅ **默认只预览** —— 加 `--apply` 才真改；随时可回滚
- ✅ **中文友好** —— 完整支持中文文件名与中文内容识别

## 依赖安装

与 `rename_kit`（零依赖）不同，本工具需要读各种文档格式，因此有依赖：

```bash
# Python 库
pip install python-docx openpyxl python-pptx pypdf

# 系统工具（PDF 提取 + 图片 OCR）
# Ubuntu / Debian
apt install poppler-utils tesseract-ocr tesseract-ocr-chi-sim

# CentOS / RHEL / OpenCloudOS
dnf install poppler-utils tesseract tesseract-langpack-chi_sim
```

> 💡 只处理纯文本/Word 的话，`python-docx` 一个就够；其余依赖按需安装。
> 缺哪个格式的依赖，那个格式就会提取不到内容（会标「未分类」），不影响其它格式。

## 快速开始

```bash
# ① 预览（读内容 → 显示会归成哪类）
python classify_kit.py --dir "./文档"

# ② 确认后执行
python classify_kit.py --dir "./文档" --apply

# ③ 反悔了一键回滚
python classify_kit.py --rollback "./文档/_classify_log_20261007_155907.json"
```

预览长这样：
```
原文件名              识别为      分    字数   新文件名
文档1.docx            合同      24.0   217   DOC_合同_文档1_2610070915.docx
工作簿1.xlsx          报价单     16.8    75   XLS_报价单_工作簿1_2610070915.xlsx
随便写写.docx          未分类      0.0    28   DOC_未分类_随便写写_2610070915.docx
```

加 `--verbose` 还能看到每个文件的**前三名候选及得分**，方便判断准不准。

## 命名规则

### 公式

```
[类型]_[分类]_[清理后原名]_[版本]_[YYMMDDHHMM].[后缀]
  ↓      ↓         ↓           ↓        ↓
 DOC    合同   采购合同        v1    2609151030
```

### 时间戳读法

```
2609151030  =  26 年 09 月 15 日 10:30
2610070915  =  26 年 10 月 07 日 09:15
```

取值来源：**文件修改时间**（所以同一文档的不同版本，时间戳天然不同）。

### 类型前缀

| 前缀 | 格式 |
|---|---|
| `IMG` | jpg / jpeg / png / gif / webp / bmp / tiff |
| `DOC` | docx / md / txt / rtf |
| `XLS` | xlsx / csv |
| `PPT` | pptx |
| `PDF` | pdf |
| `FILE` | 其它格式 |

## 分类怎么判（算法）

```
1. 提取文本（按格式选方法，最多读 12000 字）
      ↓
2. 对 38 个分类逐个打分
      强特征词命中 = +3 分
      一般词命中   = +1 分
      同词多次出现 = 每次 +0.2（最多 5 次）
      ↓
3. 门槛判定：总分 ≥ 4 且 明显领先第二名 → 定类
      否则 → 标「未分类」（不硬猜）
```

**设计取舍**：宁可标「未分类」让你人工看，也不要误判成错类别 —— 后者更难发现。

## 参数详解

| 参数 | 说明 | 默认 |
|---|---|---|
| `--dir PATH` | 目标文件夹 | 必填 |
| `--apply` | 真正执行（不加则只预览） | 关闭 |
| `--rollback FILE` | 按日志回滚 | — |
| `--no-date` | 不加时间戳（默认会加 YYMMDDHHMM） | 开启时间戳 |
| `--verbose` | 显示前三名候选及得分 | 关闭 |
| `--sep CHAR` | 分隔符 | `_` |

### 组合示例

```bash
# 先看每个文件的候选得分（判断准不准）
python classify_kit.py --dir "./文档" --verbose

# 不要时间戳（保持原样只加分类）
python classify_kit.py --dir "./文档" --no-date --apply
```

## 三级防冲突

| 层级 | 场景 | 处理 | 示例 |
|---|---|---|---|
| **1** | 不同时间保存的版本 | 时间戳区分 | `_2610070915` vs `_2610071045` |
| **2** | **同一分钟内**的同名文件 | 加序号 | `_2610071005` vs `_2610071005_02` |
| **3** | 疑似同一文档多份 | **主动列清单报告** | 见下 |

```
⚠️  发现 1 组疑似同名文档（可能是同一文档的多个版本）：
  · DOC_方案  →  4 份
        DOC_方案_2610070915.docx
        DOC_方案_2610070945.docx
        DOC_方案_2610071005.docx
        DOC_方案_2610071005_02.docx
  → 日期已把版本区分开；如需精简，请确认后手动删除过期版本
```

**它从不删文件** —— 只报告，删不删你决定。

## 安全设计

1. **默认只预览** —— 不加 `--apply` 一个文件都不动
2. **日志留痕** —— 每次执行写 `_classify_log_YYYYmmdd_HHMMSS.json`
3. **一键回滚** —— 按日志逆序还原
4. **不覆盖不删除** —— 重名自动加序号

```bash
python classify_kit.py --rollback "./文档/_classify_log_20261007_155907.json"
```

## 扩展你自己的分类

打开 `classify_kit.py`，在 `CATEGORIES` 字典里加一段：

```python
"无人船项目": {
    "strong": ["无人船", "船体", "推进器", "自主航行", "遥控"],
    "weak": ["水域", "船载", "航行", "水面"],
},
```

**写法要点**：
- `strong` 放**这个类别独有**的词（辨识度高，权重 3）
- `weak` 放常见的通用词（权重 1）
- 这样加多少类都不会互相干扰

## FAQ

**Q：识别错了怎么办？**
A：先跑 `--verbose` 看候选得分。如果某类总是错，把该类的关键词改准（加独有的强特征词）。改完重跑即可。

**Q：会改坏我的文件吗？**
A：不会。只改文件名，不动内容；默认预览；可一键回滚；从不删除、不覆盖。

**Q：扫描版 PDF 能识别吗？**
A：目前 PDF 走文本提取（pdftotext）。如果是纯扫描图片型 PDF，提取不到文字 → 会标「未分类」。可以先把 PDF 转成图片再跑（会走 OCR 路径）。

**Q：处理 1000 个文件要多久？**
A：取决于格式。纯 Word/文本很快（几十秒）；带 OCR 的图片较慢（每张 1-3 秒）。

**Q：能递归处理子文件夹吗？**
A：目前只处理指定目录的第一层，不递归。

**Q：为什么有的文件标「未分类」？**
A：内容里没有足够的特征词（比如随手写的便签）。这是**有意设计**——宁可标未分类，也不要猜错。

## 工作原理

```
扫描目录
   ↓
按扩展名分发到对应的文本提取器
   （PDF→pdftotext / Word→docx / 图片→OCR ...）
   ↓
提取正文（最多 12000 字）
   ↓
38 个分类加权打分（强特征词 3 分 / 一般词 1 分）
   ↓
门槛判定（≥4 分且领先）→ 定类 或 标「未分类」
   ↓
生成新文件名（前缀 + 分类 + 原名 + 版本 + YYMMDDHHMM）
   ↓
冲突处理（序号）+ 疑似同名检测
   ↓
预览  →  确认  →  执行 + 写日志
```
