> 把乱七八糟的文件名，一键规范成「以后能找到」的样子。

## 为什么需要它

你的文件夹是不是长这样？

```
Logo image 头像 用于自媒体的头像图片.png
双鱼封面 final 版.png
内容排期表（2026Q4）.xlsx
第1讲 PPT 最终版.pptx
报告 v2 最终版.pdf
头像1.png  头像10.png  头像2.png      ← 排序全乱
```

**五个常见问题**：

| 问题 | 后果 |
|---|---|
| 文件名带空格 | 命令行、脚本、网页上传时容易出错 |
| 中英混杂（`image` + `头像`）| 以后搜索时记不清用的哪个词 |
| "最终版 / 最终版2 / 真最终版" | 版本管理彻底失控 |
| `头像1` `头像2` `头像10` | 排序错乱（10 排在 2 前面）|
| 混放多种类型文件 | 想找图片得一个个看扩展名 |

`rename_kit` 一次解决全部问题。

## 特性

- ✅ **自动加类型前缀** —— `IMG` / `DOC` / `XLS` / `PPT` / `PDF` / `AUD` / `VID` / `ZIP`
- ✅ **默认只预览** —— 不加 `--apply`，一个文件都不动
- ✅ **可一键回滚** —— 每次执行写日志，随时还原
- ✅ **中文友好** —— 完整支持 UTF-8 文件名
- ✅ **零依赖** —— 只用 Python 标准库，不用装任何包
- ✅ **不覆盖文件** —— 重名自动加序号
- ✅ **智能补零** —— `头像1` → `头像01`，排序正确

## 快速开始

```bash
# ① 预览（默认模式，只显示会改成什么，不改文件）
python rename_kit.py --dir "/你的文件夹"

# ② 确认没问题，执行
python rename_kit.py --dir "/你的文件夹" --pad --apply

# ③ 反悔了，一键回滚
python rename_kit.py --rollback "/你的文件夹/_rename_log_20261007_150351.json"
```

**耗时**：千个文件大约 1 秒。

## 命名规则

### 公式

```
[类型前缀]_[清理后的名字]_[版本或日期].[后缀]
```

### 类型前缀对照表

| 前缀 | 覆盖格式 |
|---|---|
| `IMG` | jpg / jpeg / png / gif / webp / bmp / svg / ico / heic / psd / ai |
| `DOC` | doc / docx / md / txt / rtf / odt |
| `XLS` | xls / xlsx / csv / ods |
| `PPT` | ppt / pptx / key / odp |
| `PDF` | pdf |
| `AUD` | mp3 / wav / m4a / flac / aac |
| `VID` | mp4 / mov / avi / mkv / webm |
| `ZIP` | zip / rar / 7z / tar / gz |
| `FILE` | 其它未识别的格式 |

### 示例

**图片**
```
IMG_头像_双鱼不摸鱼_圆形_01.png
IMG_Logo_双鱼不摸鱼_横版_v02.png
IMG_封面_第01期_融合脸实验_16x9.jpg
IMG_头像01.png  IMG_头像02.png  IMG_头像10.png
```

**其它类型**
```
DOC_脚本_第01期_融合脸实验.docx
XLS_内容排期表2026Q4.xlsx
PPT_第1讲_肖像保护.pptx
PDF_报告_v02.pdf
```

## 参数详解

| 参数 | 说明 | 默认 |
|---|---|---|
| `--dir PATH` | 目标文件夹（必填） | — |
| `--apply` | 真正执行（不加则只预览） | 关闭 |
| `--rollback FILE` | 按日志文件回滚 | — |
| `--pad` | 末尾数字补零（`头像1` → `头像01`）| 关闭 |
| `--date` | 文件名末尾加修改日期 `YYYYMMDD` | 关闭 |
| `--lower` | 文件名全部转小写 | 关闭 |
| `--sep CHAR` | 分隔符（默认下划线 `_`，可改 `-`）| `_` |

### 组合示例

```bash
# 报告类文件：加日期，方便按时间排序
python rename_kit.py --dir "./报告" --date --apply
# → PDF_肖像监测_20261007.pdf

# 英文素材：全小写 + 短横分隔
python rename_kit.py --dir "./assets" --lower --sep - --apply
# → img_logo-horizontal-v02.png

# 全套整理（推荐）
python rename_kit.py --dir "./素材库" --pad --apply
```

## 安全设计

工具做了三层保护：

### 第一层：默认不执行
不带 `--apply` 时，**只打印预览清单**，一个文件都不会动。

### 第二层：日志留痕
每次执行都在目标目录生成：
```
_rename_log_20261007_150351.json
```
里面完整记录：哪个文件改成了什么名、什么时间、哪个目录。

### 第三层：一键回滚
```bash
python rename_kit.py --rollback "/path/_rename_log_20261007_150351.json"
```
按日志逆序还原，**回到执行前的状态**。

> 实测：9 个文件重命名后回滚，全部准确还原。

## FAQ

**Q：会不会误改我的文件？**
A：不会。默认预览模式；即使执行了，也能一条命令回滚。而且它**从不删除、不覆盖**——遇到重名只会加 `_01` 后缀。

**Q：支持中文文件名吗？**
A：完全支持（UTF-8）。中文、日文、emoji 都没问题。

**Q：会处理子文件夹吗？**
A：目前只处理**指定目录的第一层**，不递归。子文件夹里的文件需要单独跑（或等后续版本支持 `--recursive`）。

**Q：我的文件名有版本号，会被改乱吗？**
A：不会。`v2`、`v02` 这类版本号会被保留；`--pad` 只补零"非字母后"的末尾数字，`2026Q4` 不会被改成 `2026Q04`。

**Q：哪些"废话词"会被自动去掉？**
A：`最终版`、`最新版`、`修改版`、`副本`、`的副本`、`copy`、`final`、`new`，以及孤立的「版」字。

**Q：改完之后日志文件碍事怎么办？**
A：确认没问题后手动删掉即可。工具本身会跳过 `_rename_log_*` 文件，不会重复处理它。

## 工作原理

```
扫描目录
   ↓
识别每个文件的扩展名 → 匹配类型前缀
   ↓
清理文件名主体（去空格/非法字符/废话词）
   ↓
加前缀 + 可选的补零/日期/小写
   ↓
检查冲突（与现有文件 + 计划内部）→ 重名加序号
   ↓
输出预览清单  →  等待确认
   ↓
执行重命名 + 写日志
```
